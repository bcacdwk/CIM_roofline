# CIM Roofline 计量约定

版本：`v0.1-candidate`

状态：**Task 0 修订候选，待审阅**

适用：resident–streaming 理论基线；不包含已验证的器件标定。

## 1. 对象、边界与配置

分析对象是指定配置、计算模式下的 CIM 求值服务单元：一个 macro，或为完成声明的逻辑运算而明确组合的 macro 组。固定输入接收、驻留写入与规定输出完成的边界。配置包括逻辑阵列尺寸、参与的 macro/bank 数、两侧精度和必要的求值／写入模式，推导中不得悄悄换范围。

默认采用服务单元的**逻辑 streaming 输入 payload**，不是 GPU/HBM 流量或 ADC 输出量。`Q_S` 与 `ρ` 同输入口径，`Q_R` 与 `τ` 同逻辑写入口径；四者须描述相同硬件范围和兼容配置。单 macro 能力不能直接配整模型的唯一张量字节。跨单元汇总须交代映射、重复服务、共享资源与能力归约；分别相加字节和速率不足以预测系统性能。

## 2. 两侧需求：逻辑 payload 累计量

**Q_S** 是窗口内由声明边界接收并服务的 streaming 操作数字节累计量。

- 不同求值调用、分块或重放使同一输入重新进入边界，按实际服务次数计数。
- 完成同一次逻辑服务的内部广播、位串行展开和多次 ADC 转换不重复计数。不同逻辑服务的重复输入与一次服务的物理步骤必须分开。
- 若统计独立接收端口，一份广播在各接收端分别贡献需求；这不是上游共享总线的重复传输量。
- 输出不直接加入当前 `Q_S`，但规定输出所需 sensing、ADC、数字累加和读出时间必须进入服务能力及边界。输出成为后续 CIM 求值输入并重新进入边界时，在后次输入服务中计数。Attention 两次矩阵运算分别计 query 输入和第二次运算的注意力系数输入，第一次输出不另加一次；中间处理范围须声明。

`Q_S` 的规模增长由 workload 与映射决定，不通用假设与序列长度线性。

**Q_R** 是窗口内 workload／映射为建立、更新或重载可计算驻留状态发出的逻辑写入 payload 累计量，不是容量或唯一权重大小。包括窗口内初始装载、实际参数更新、KV append、容量／映射／调度触发的重载及同一数据的多次逻辑重写。一个事务的编程脉冲、verify 重试和内部编码计入服务代价，不按脉冲重复增加 payload。

## 3. 服务能力、精度、维护与寿命

**ρ** 为指定模式下完成流式求值的输入 payload 服务能力上限：每服务间隔完成的逻辑输入 Byte / 服务间隔。ACIM 转换、阵列响应、读出，DCIM 数字求值、位串行及累加等必要步骤均影响间隔。单次 latency 与稳态 initiation/service interval 分开；流水线中不能默认取 latency 的倒数。有限窗口还可能有填充、排空代价。ADC／输出指标反推输入率须显式换算，不能直接等同。

**τ** 为指定写入模式下使逻辑 resident payload 可计算的服务能力上限；分母含必要编程、校验及适用擦除。小粒度更新与整页／整块更新不能无条件共用有效 `τ`。本轮不新增写放大模型。`ρ,τ` 是配置／模式能力，不是材料固有常数，也不能由待预测任务的实际 `T` 反算后再宣称独立预测。

分别声明 `b_S,b_R`，单位 Byte/element。INT4 为 0.5 Byte/element；8-bit 权重为 1 Byte 逻辑 payload，不表示一个物理 cell 存储 8 bit。位切片、冗余编码、总线填充、位串行和内部编程开销由实现映射和能力体现，不能在需求与速率中重复惩罚。本文 `M` 为有用 OP 总数，稠密算例 `1 MAC = 2 OP`；`1 Byte = 8 bit`，`GB = 10^9 Byte`，`GiB = 2^30 Byte`，`TOPS = 10^12 OP/s`。

内部 refresh、破坏性读后 restore 不伪装成 workload 更新；其代价进入相应服务周期、可用能力或明确的共享资源限制。未可靠计入时标为“忽略该项的乐观上界”，不得称已摊销或无代价。耐久度、目标寿命单列为部署可行性约束；没有寿命、使用强度和写入分布假设，不将寿命平均允许写入率混进 `τ`。

## 4. 窗口与映射

分析工作窗口 `W` 与完成时间 `T` 分开。优先采用稳态代表工作单元；prefill 等有限阶段需声明起止、初始驻留状态及窗口内写入。Decode 以给定上下文状态分析，不将增长会话称为完全相同的无限重复周期。

每轮实际发生的重载、KV 建立或参数更新必须计入。一次装载只在明确的预装载稳态分析中可排除；冷启动或有限会话不能无条件忽略。仅当同一模式完整重复、两侧需求同比例增长时 `RI` 不变；任意改变窗口不保证不变。本轮删除 `dQ_R/dt` 派生定义；`Q_R/T` 是执行产生的平均率，不是天然与硬件无关的算法常数。

`Q_S,Q_R,RI` 由 workload、窗口、精度和映射共同确定。容量可通过重载影响 `Q_R`，分块重放也可影响 `Q_S`。理想参考映射须标明；目标硬件不支持时必须重新计数。下一轮固定输入为：硬件边界／配置／精度／服务间隔口径；workload 窗口／初始状态／驻留策略／映射／两侧 payload。

## 5. 上界、换算与优化

对 `Q_S > 0, Q_R ≥ 0` 及适用的正能力 `ρ,τ`：

`T ≥ max(Q_S/ρ, Q_R/τ)`；动态分支 `RI = Q_S/Q_R`，`P = Q_S/T ≤ min(ρ, τ·RI)`，`RI* = ρ/τ`。`Q_R = 0` 时取 `RI = ∞`，直接使用 `P ≤ ρ`，不计算 `M/0`。不支持写入的单元不能承接动态分支；静态分支只需适用的正 `ρ`。

`max` 下界不要求完全重叠；重叠、共享资源、依赖和利用率影响能否接近它。多 macro/bank 错峰只是可能途径，不保证同一资源预算能同时达到两路独立峰值。明确互斥且两项分别是必要占用时间的情形，`T ≥ Q_S/ρ + Q_R/τ` 更紧，原下界仍成立。以 `ρ` 运行的 resident 对应需求率为 `ρ/RI`。

同一次执行中 `κ_S = M/Q_S`、`P_OP = M/T = κ_S·P`。动态分支可加 `κ_R = M/Q_R`，得到 `RI = κ_R/κ_S`、`P_OP ≤ min(κ_S·ρ, κ_R·τ)`；静态分支仅用 `P_OP ≤ κ_S·ρ`。系数绑定任务与映射，不是通用跨架构硬件等价。GPU 流量另记 `Q_GPU`，按其层级和执行计数；不假设 `Q_GPU = Q_S + Q_R`，主文不保留一般横轴变换。

`P` 是输入服务吞吐。静态分支不意味着规模、batch、序列长度与延迟／token/s 无关。不同任务不可仅以输入 Byte/s 比较；同一任务优化同时考察 `T`、任务吞吐或有用 OP/s。ridge 只表示两路需求时间平衡，不自动表示最好性能或成本。增加重复输入、无用工作或降低 `ρ` 以接近 ridge 不构成性能优化。
