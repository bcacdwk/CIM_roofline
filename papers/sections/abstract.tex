\begin{abstract}
From CPUs to GPUs, the Roofline model has become a textbook tool for revealing a platform's performance ceiling and how well a workload matches it. Compute-in-memory (CIM), however, falls outside this picture because it violates the core Roofline assumption of separate compute and memory. We present a resident-streaming Roofline model for CIM, in which streaming-activation and resident-weight throughputs replace compute throughput and memory bandwidth, respectively. This follows from a symmetry we observe: conventional processors pair heterogeneous hardware with homogeneous data, whereas CIM pairs homogeneous hardware with heterogeneous data---operands residing in the array and operands streaming through it. Using NeuroSim with literature-extracted parameters, we place ten CIM technologies, from SRAM to emerging non-volatile memories, on this Roofline and quantify the demands of mainstream large language models across computation stages. The model explains why write speed is critical in CIM: like GPU bandwidth, it caps throughput whenever reuse falls below a critical value, which spans over four orders of magnitude across these memory technologies. Likewise, the throughput at which activations stream through the CIM array plays the role of GPU compute throughput and represents the true computing performance of CIM.
\end{abstract}
