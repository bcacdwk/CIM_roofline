\section{Hardware and Workload Characterization}
\label{sec:characterization}

Fig.~\ref{fig:hardware-capacities}(a) presents $\rho$ and $\tau$ estimated using NeuroSim~\cite{lee2024neurosim,peng2019dnnneurosim} with literature-extracted parameters for SRAM DCIM~\cite{SDCIM-01,SDCIM-03,SDCIM-05}, SRAM ACIM~\cite{SACIM-03,jia2022imc,SACIM-05}, 2D NOR~\cite{NOR-01,NOR-02,NOR-04}, 3D NAND~\cite{NAND-04,NAND-05,NAND-06}, RRAM~\cite{RRAM-05,RRAM-01,RRAM-06}, STT-MRAM~\cite{MRAM-06,MRAM-03,MRAM-04}, PCM~\cite{PCM-03,PCM-01,PCM-06}, FeRAM~\cite{FERAM-03,FERAM-04,FERAM-02}, eDRAM~\cite{GC-04,GC-02,GC-05}, and 3D FeNOR~\cite{FENOR-02,FENOR-01,FENOR-04}. Common peripheral assumptions~\cite{CMOS-02,CMOS-03,CMOS-07} and logical-byte accounting provide a consistent comparison while retaining native array sizes and update organizations. These are macro-level calculation and update rates, including required erase, verification and refresh costs, rather than the aggregate I/O bandwidth of a multi-bank system. Three paired scenarios per configuration reflect literature-informed parameter ranges. In log space, each circle passes through the two alternative points with its center nearest the reference point; it visualizes scenario spread rather than a capability boundary.

Points toward the upper right provide higher throughputs for both services, while the diagonal guides mark constant $\SI^*$. Above $\rho=\tau$ (yellow), resident updates are slower per byte than streaming calculation; below it (blue), the reverse holds. 3D FeNOR lies close to this diagonal, with relatively balanced streaming and resident throughputs.

Within each scenario, $\rho$ varies across technologies by about $10^2$, but $\tau$ by over $10^4$: similar peripheral conditions constrain streaming calculation, whereas write mechanisms and update parallelism differ greatly. Reference SRAM ACIM and NOR illustrate this distinction: their streaming rates are about 40 and 24\,MB/s, but resident rates are 3200 and 0.080\,MB/s, respectively, leading to very different reuse requirements. Storage density, however, also matters in technology selection. Fig.~\ref{fig:hardware-capacities}(b) adds independent binary cell/tile density and normalized footprint estimates from reported geometry and conditional models~\cite{NOR-GF28-2023,PCM-PALHARES-2024,FERAM-07-JEDS}, including a 500-layer projection of NAND geometry~\cite{NAND-04}. Compact storage can make slower-updating technologies attractive for retaining large resident states, so the upper-right position alone is not a sufficient selection criterion.

Table~\ref{tab:workload-intensity} reports $\SI$ for 72 matrix-stage operating points derived from six fixed model configurations~\cite{qwen35,ministral3,qwen36,hy3,ling,mimo}, using one byte per element. Weight projections and FFN/MoE follow the one-load accounting of Section~\ref{sec:model}-C, counting shared branch inputs once and each subsequent stage's new input separately. For causal grouped-query attention (GQA), $H_q$ and $H_{\mathrm{kv}}$ denote query and KV head counts, and $d_{\mathrm{QK}}$ and $d_V$ the query/key and value dimensions. Counting queries and attention coefficients as streaming inputs and writing each token's KV once, prefill from an empty cache to length $L$ gives
\begin{equation}
 Q_S=LH_q[d_{\mathrm{QK}}+(L+1)/2],\quad
 Q_R=LH_{\mathrm{kv}}(d_{\mathrm{QK}}+d_V).
 \label{eq:attention-prefill}
\end{equation}
Decode appends one token to reach $L$: omit the leading $L$ in both counts and replace $(L+1)/2$ by $L$ in $Q_S$.

The increases in $\SI$ in Table~\ref{tab:workload-intensity} have different origins. For weight stages, larger $U$ spreads a fixed load over more input vectors, reducing resident writes per use. For attention decode, larger $L$ increases streaming work per token, while the logical KV write volume per token remains fixed. The resulting higher $\SI$ therefore accompanies more calculation and a larger cache: sustaining the same token rate requires greater streaming throughput and storage capacity.
