# 方法检验与质量记录

## 方法适用性与必要记录

1. **R4及现有组合接口可完整表达本例。** 未发现现有方法实质无法表达的反例，不要求修改共同公式。调用完整周期时需明确机器可读覆盖清单：`dcim_service`无“完整MAC槽已含read”的参数，`direct_service`也总加入公共前端。本例按原生完整MAC槽调用共享DCIM计数/服务接口（独立read额外时间为0，边界先为0），再用共享`program_sequence_ns`只补两拍全向量捕获/提交。写侧先调用共享`direct_service`取得逻辑粒度、批数和未替代前端，再以同一共享完整操作块函数组合不带额外前端的完整memory周期。每一情景的覆盖列表和被替代时间均保存在results.json；没有另写服务公式。API覆盖mask只是可选便利；现有组合接口已足够。
2. **静态SRAM读服务槽不等于字线切换数。** D6CIM bit-first accumulation在八个输入位期间保持读连接；本映射有512个MAC槽、64次行组选择。共享`read_rounds`仍保留为512个带读的服务槽，不能将其解释成512次WL切换。由于读阶段完整覆盖，这个命名差异不影响当前时间；若将来拆分读能量或首次建立代价必须细化。
3. **原生精度/维度/归约资源必须与宏时钟成套使用。** 原128×128 bit只对应128×16 INT8，64clock不是128输出的完整MVM。R0的32项/轮与原生16项/轮分别得到256和512轮，二者是不同结构，而非共享算术错误。8个容量分片已安装128条但活动16条HCA/BFA，不能把安装数自动算成并行服务。
4. **写侧移植条件仍主导证据不确定性。** D6原128bit普通写口没有独立memory-write ns。CMOS-07给出48bit 8T同步组织、连续写图和典型455MHz；其1.54ns只读访问被明确排除。CMOS-03给6T周期末成功终点与约1ns瞬态模型交叉支持。采用的2.2/5/10ns属于条件性预算，不声称同芯片、同固定电压的配对硅测。
5. **两路峰值不等于可重叠吞吐。** 本服务单元仅一片活动、一个控制/更新域，memory与compute顺序执行；在确切互斥下，累计两路必要占用之和可比roofline的max下界更紧。这里没有进行workload预测。
