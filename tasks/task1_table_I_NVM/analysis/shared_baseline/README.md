## 推荐配置

- 一份 128×128 逻辑 INT8 矩阵；`b_S=b_R=1 Byte/element`，每向量 128 Byte 输入，输出寄存器为 128×24 bit。边界从本地宽向量输入接收到本地结果就绪，不含上游/下游传输。resident 边界从本地写事务到状态可计算。
- 28 nm、参考 0.9 V/25°C；使用近标称模式的工程时间预算，来源条件原样保留。单个局部更新域，无独立服务单元复制加速。
- ACIM：一位二电平输入，八个二进制权重位平面并行，每平面 16 个 SAR（总 128），每 ADC 共享八列；每共享组重新建立与求值。名义十位 SAR、约八位有效精度，近似部分和重构到 24-bit 容器；64 次物理服务/向量，每批两拍数字重构。
- DCIM：输入位串行、八位权重并行、32 输入项/组、16 输出通道，共 256 步/向量；精确整数结果。两种路径都另有两拍输入捕获/最终提交。
- 128 路物理编码 bit 的本地写接口；驱动同时完成多少 cell，由介质的电压/电流/原生操作限制决定。页/块保留天然粒度，有效写入字节只计本逻辑状态真正更新的部分。

| 公共量 | 范围 | 推荐 | 粒度 |
|---|---:|---:|---|
| 输入形成 `T_I` | 2–10 ns | 5 ns | 每物理求值步骤，公共复位/二电平输入与缓冲 |
| SAR 读出 `T_A` | 10–50 ns | 20 ns | 每 ADC 每样本完整可复用时隙，一批同时转换 |
| 数字节拍 `T_D` | 2–10 ns | 5 ns | 公共数字阶段；完整服务需另乘实际拍数 |
| 写控制 `T_W=2T_D` | 4–20 ns | 10 ns | 每事务准备与完成；编程/校验/专用驱动另计 |

主参考顺序调度给出：

```text
Δ_S,ACIM = 64 (T_I + t_m,A + T_A + 2 T_D) + 2 T_D
Δ_S,DCIM = 256 (t_m,D + T_D) + 2 T_D
```

同一完整周期包含了多个阶段时，用整体证据替代所含阶段。公共外围占用本身不是某介质的 streaming 周期。JSON 保存的两个算例使用合成物理时间，仅验证方法。

## 审阅时最关键的选择

1. **精度合同**：推荐保留相同 INT8 输入/权重和输出容器，同时明确 ACIM 为近似重构、DCIM 为精确整数。若本表必须比较“相同最终误差/精确性”，需增加精度约束，可能改变 ACIM 分组、位宽和服务次数；这是当前最实质的口径选择。
2. **资源和调度**：推荐以八个位平面并行、总 128 个 ADC、16 条数字输出通道和顺序调度作为可解释的 v0.1 起点。它不是等面积方案。减少 ADC、改为模拟保持复用或改变 DCIM 并行度，均需全体介质统一重算。
3. **天然更新粒度**：推荐保留真实 page/block，在同一局部映射上计有效逻辑字节与完整服务；预擦除 append 和循环重写单列。遇到大页不把页中无关容量记成当前矩阵的有效更新。
