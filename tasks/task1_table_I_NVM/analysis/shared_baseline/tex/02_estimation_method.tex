\section{\texorpdfstring{局部 CIM 的 $\rho$、$\tau$、$\RI^*$ 通用估算方法}{局部 CIM 的 ρ、τ、RI* 通用估算方法}}

\subsection{服务粒度与总关系}

先确定一次完成的逻辑字节，再数实际操作，最后累加完整服务时间。一个 streaming 事务完成 $B_S$ Byte 输入的规定求值与输出；一个 resident 事务完成 $B_R$ Byte 可计算状态。其服务间隔分别为 $\Delta_S$、$\Delta_R$，则
\begin{equation}
\boxed{\rho\approx B_S/\Delta_S,\qquad \tau\approx B_R/\Delta_R,\qquad
\RI^*\approx\frac{B_S}{B_R}\frac{\Delta_R}{\Delta_S}.}
\label{eq:service}
\end{equation}
时间以秒代入得到 Byte/s；以 ns 代入 $B/\Delta$，数值恰为十进制 GB/s。$\RI^*$ 无量纲。$B_S,B_R$ 是单次服务粒度，$Q_S,Q_R$ 是 workload 窗口内累计的逻辑输入与更新量。内部位展开、转换与 verify 增加占用，同一次逻辑 payload 只计一次。

该逻辑任务 $B_S=128$ Byte；完成 16 个 INT8 权重时 $B_R=16$ Byte，ridge 的粒度因子为 8；有效页为 256 Byte 时该因子为 $1/2$。均匀事务聚合时字节和全部服务时间同比增加，$\tau$ 保持不变。Roofline 上界为 $P\leq\min(\rho,\tau\RI)$；静态 $Q_R=0$ 分支为 $P\leq\rho$。两路能力是同一实现分别服务时的估计，共享资源的争用决定能否同时接近上界。

\subsection{A. ACIM streaming：求值、转换与重构分别计数}

\textbf{通用模板。} 对按输入分片、行组和权重平面组顺序覆盖一次 MVM 的映射，令每片处理 $u$ 个输入 bit、每行组 $r$ 个输入项、共 $W$ 个权重平面且每次并行 $w$ 个，则基础组合数为
\[
F=\left\lceil\frac{8b_S}{u}\right\rceil
  \left\lceil\frac{n_{\rm in}}{r}\right\rceil
  \left\lceil\frac{W}{w}\right\rceil .
\]
每个组合把输出划为 $J$ 个\emph{求值组}，组宽 $e_j$，满足 $\sum_j e_j=n_{\rm out}$。每个活动平面有 $a$ 个 ADC，故组 $j$ 需 $\lceil e_j/a\rceil$ 个转换批次；批 $b$ 实际包含 $o_{jb}\leq a$ 个输出。数字重构有 $d$ 条输出通道，每轮处理不超过 $d$ 个输出、用 $k_A$ 拍完成该组位权合并与累加。于是
\begin{equation}
\begin{aligned}
N_E&=FJ, &N_C&=F\sum_j\left\lceil e_j/a\right\rceil,\\
N_{\rm rec}&=F\sum_j\sum_b\left\lceil o_{jb}/d\right\rceil,
&N_{\rm dig}&=k_A N_{\rm rec}.
\end{aligned}
\label{eq:acount}
\end{equation}
$N_E$ 是并行阵列求值轮数，$N_C$ 是并行转换批数，$N_{\rm dig}$ 是数字总拍数。尾组按实际宽度计，空 ADC 槽不产生有用结果。每平面每输出产生一个码且无模拟位权合并时，有用标量转换数为“输入分片数 $\times$ 行组数 $\times Wn_{\rm out}$”。多位输入或多级/差分映射先说明码范围、符号处理和重构方式，再由其实际循环推导这些次数。

在各阶段顺序执行、每轮时间相同的情景下，
\begin{equation}
\boxed{\Delta_{S,A}=N_E(T_I+t_{m,A})+N_C T_A+N_{\rm dig}T_D+T_H+c_0T_D.}
\label{eq:acim}
\end{equation}
这里 $t_{m,A}$ 是一次并行求值的阵列响应、专用前端及必要恢复，$c_0$ 为边界拍数；不同轮的负载或恢复不同则逐项求和。$T_H$ 为额外保持电路的采集、建立、复位等串行开销总和，ADC 自带单样本采样仍计在 $T_A$。

\textbf{共享如何影响求值。} 每组只求 $e_j\leq a$ 个输出，转换后再建立下一组时，$N_E=N_C$，可以取 $T_H=0$。若一次求出更多输出，保存在独立模拟节点后分批转换，则 $N_E<N_C$：必须有至少 $w\max_j e_j$ 个同时保持的有效样本槽、隔离开关及缓冲，且在最后一批读出前满足误差与保持要求。若转换和数字处理交替顺序执行，保持窗口保守取该组的全部 $\sum_b[T_A+k_A\lceil o_{jb}/d\rceil T_D]$；这段等待已经包含在服务时间中。保持负载增加的求值建立放入 $t_{m,A}$，额外采集等放入 $T_H$。持续驱动阵列维持结果也可分批读出，但须计其占用与稳定条件。选择哪种组织，由实际资源与介质兼容性决定。

\textbf{R0 代入。}$u=1,r=128,W=w=8$，故 $F=8$；八个求值组各宽 16，$a=d=16,k_A=2,c_0=2$，无跨组模拟保持。因此
\[
(N_E,N_C,N_{\rm rec},N_{\rm dig})=(64,64,64,128),\quad
8192=8\times128\times8=64\times128,
\]
\[
\Delta_{S,A}=64(T_I+t_{m,A}+T_A+2T_D)+2T_D.
\]
R0 每向量需 64 次求值和 64 批转换，完成的输入 payload 为 $B_S=128$ Byte。增加 ADC 而保持数字通道数时，转换批次可减少，数字重构总拍数却未必同比减少。

\subsection{B. DCIM streaming：映射决定计算轮数}

\textbf{通用模板。} 每轮处理 $u_D$ 个输入 bit、$v_D$ 个权重 bit、$r_D$ 个输入项和 $d_D$ 个输出，对应的整数乘法/归约资源必须具备这些宽度。顺序遍历各组时，
\begin{equation}
N_D=\left\lceil\frac{8b_S}{u_D}\right\rceil
\left\lceil\frac{8b_R}{v_D}\right\rceil
\left\lceil\frac{n_{\rm in}}{r_D}\right\rceil
\left\lceil\frac{n_{\rm out}}{d_D}\right\rceil,\qquad
\Delta_{S,D}=N_{\rm rd}t_{m,D}+N_D k_DT_D+T_L+c_0T_D.
\label{eq:dcim}
\end{equation}
$k_D$ 是完成每轮计算、符号处理和累加所需的数字拍数；$N_{\rm rd}$ 是实际物理读侧服务次数，$t_{m,D}$ 包括必要恢复。每轮重新读取时 $N_{\rm rd}=N_D$、额外锁存开销 $T_L=0$。若一组权重读入后复用于多轮输入，按真实装入次数计 $N_{\rm rd}$，并声明锁存容量、读出接口与额外装入开销 $T_L$。全字并行、输入位串行和双边位串行均由式中的两个位宽因子表达。

\textbf{R0 代入。}$u_D=1,v_D=8,r_D=32,d_D=16,k_D=1,c_0=2$，每轮重新服务读侧，得到
\[
N_D=8\times1\times4\times8=256,\qquad
\Delta_{S,D}=256(t_{m,D}+T_D)+2T_D.
\]
一轮归约 32 项并更新 16 个输出；256 轮完成同一份 128 Byte 输入，交付全部 128 个结果。原 \sid{SDCIM-01} 的 64 拍对应 $128\times16$ VMM 及其 16 项局部归约；本文的 32 项分组是另一个参考选择，计数由本映射产生。\cite{SDCIM-01}

\textbf{顺序与流水的使用。} 上述顺序公式的服务间隔等于完整串行时长。若相邻操作能在阵列、ADC 和数字级之间流水，先核对各级独立资源、缓冲容量及依赖，再按最慢级的\emph{每向量占用}估计稳态间隔；同一硬件承担的阶段先合计。只有满足这些条件才采用流水收益，有限窗口另计填充与排空。完整宏周期可替代已含的阶段，匹配其实际分组与拍数后使用。R0 及结构敏感性对照均用顺序调度，便于单独观察结构变化。

\subsection{C. 直接更新型 resident：完成多少权重，执行多少批}

\textbf{通用模板。} 一次事务更新 $L$ 个完整逻辑权重，每权重映射为 $c$ 个 cell，一批可同时完成 $p$ 个 cell 的完整目标状态。分组对齐、可独立选通且每 cell 一次完整更新时，物理批数 $n_w=\lceil Lc/p\rceil$；受行/平面限制时改用映射中的实际批列表。令编码装入量为 $D_{\rm enc}$ bit、接口宽 $w_{
m IO}$，数据批数 $n_b=\lceil D_{\rm enc}/w_{\rm IO}\rceil$。则
\begin{equation}
B_R=Lb_R,\quad
\Delta_R=T_{\rm front}+\sum_{j=1}^{n_w}t_{{\rm update,full},j},\quad
T_{\rm front}=[2+n_b-\chi]T_D.
\label{eq:direct}
\end{equation}
$\chi=1$ 表示首数据批与命令同拍，命令/数据分开时 $\chi=0$；事务有数据且 $n_b\geq1$。单批物理完整更新含驱动、必要脉冲与恢复，到状态可计算为止。多批数据若先装入再执行，须有相应缓冲；边装边写则按实际顺序计数据与控制。完整周期已含的接口或恢复阶段予以替代。

\textbf{R0 示意。} 取 $L=16,c=8,p=128,D_{\rm enc}=128$ bit、$w_{\rm IO}=128$ bit、$\chi=1$，故 $B_R=16$ Byte、$n_w=n_b=1$。合成物理更新时间为 50 ns、$T_D=5$ ns 时，$\Delta_R=60$ ns，$\tau=16/60\approx0.267\GBs$。若驱动只支持 64 cell 同时完成，同一事务需两批；输入只装入一次，分子仍为 16 Byte。直接更新按完整步骤识别，SET/RESET 是否对称仅辅助说明状态转换。

\subsection{D. 分步编程或含擦除摊销的 resident}

\textbf{通用模板。} 对相同 $B_R$，将预处理、编程、校验与恢复按实际顺序列出：
\begin{equation}
\Delta_R=T_{\rm front}+T_{\rm pre}
 +\sum_j(T_{{\rm drive+program},j}+T_{{\rm verify},j}+T_{{\rm recover},j})
 +T_{\rm erase,amort}.
\label{eq:program}
\end{equation}
每项是实际操作块或并行批次。若一次逻辑更新需要先 RESET 再 SET，按这两步及其并行宽度计；若程序循环 $K$ 次且每次后都校验，循环占用为 $K(t_p+t_v+t_r)$。$K$ 来自终点规则、文献分布或声明的情景。原文完整 program cycle 已含 verify/retry 时，直接使用完整块。verify 的 sensing/ADC、比较宽度与共享条件应匹配同一配置，payload 在成功完成后只计一次。

对单局部编程域，持续循环重写、每次擦除实际支撑 $N_{p/e}$ 个有效页服务时，
\begin{equation}
B_R=B_{\rm page,logical},\quad
\Delta_R=T_{\rm front}+T_{\rm program,full}+T_{
\rm erase}/N_{p/e},\qquad \tau\approx B_R/\Delta_R.
\label{eq:page}
\end{equation}
有效页字节只计本逻辑状态真正更新的部分，数据装入与时间则覆盖实际操作的全部物理页、保留内容及编码。$N_{p/e}$ 由该映射实际利用的页服务数决定。已有预擦除空间上的 append 可在声明窗口内取擦除项为零；持续重写保留摊销。跨多个页才完成一组权重时，累计这些页的全部时间和对应逻辑字节。

\textbf{R0 页示意。} 有效页 256 Byte，恰好映射为 2048 bit；命令与数据分开，$n_b=16,\chi=0$，$T_{\rm front}=18T_D$。取含 verify 的完整 program 为 $10\us$，erase 为 $200\us$，$N_{p/e}=16$，则
\[
\Delta_R=18\times5\ns+10\us+200\us/16=22.59\us,
\qquad \tau\approx0.0113\GBs.
\]
这是单域天然页操作的算术示意，没有引入 die/plane 复制并行。

\subsection{示意算例与范围传播}

以下两个算例采用不绑定具体介质的合成物理时间，说明完整服务与范围传播。示意 1 使用 A+C：三个读侧时间为 10/25/40 ns，物理更新为 20/50/100 ns，$B_R=16$ Byte。示意 2 使用 B+D：读侧为 3/10/30 ns，完整 program 为 5/10/20\,$\mu$s，erase 为 100/200/400\,$\mu$s，每次擦除支撑 16 个有效 256-Byte 页。它们分别配短、参考、长外围情景。

参考点两者都得到 $\Delta_S=3850\ns$、$\rho\approx0.03325\GBs$；写服务分别为 60 ns 与 22590 ns，所以 ridge 分别为 $(128/16)(60/3850)\approx0.1247$ 与 $(128/256)(22590/3850)\approx2.934$。读写时间之比必须与服务粒度因子一起使用。
