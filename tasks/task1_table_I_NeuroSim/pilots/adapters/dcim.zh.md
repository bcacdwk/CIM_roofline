# D6CIM pilot 适配说明

输入仍是 Step 2 的 `configs/cases/02_sram_dcim.json`；`dcim.py` 只生成执行事件与解析快照，不读取 `results.json` 或调用原计算器。公共驱动负责实际 V1.4 模块执行、完整公共寄存路径和负载初始化、时钟选择、事件计时及最后的 v3 对照。

## 阶段归属与资源

原生组织固定为 K=128、N=16，一片 128×128 bit SRAM，16 个 HCA/BFA、每轮 16 项、8 个输入位。八个行组各连续进行八个输入位轮次，共 64 个完整 MAC 周期。正常求值没有 ADC。

|阶段|提供方|次数及资源|计费边界|
|---|---|---|---|
|整向量输入捕获/接纳|公共 NeuroSim DFF 和已实例化控制路径|一次，既有 1024 bit 输入寄存|一公共拍，输入保持到全部 64 轮结束|
|完整 MAC|有来源的原生完整周期|64 次，16 个 HCA/BFA、16 项/轮|每轮 reference 5 ns；包含静态 SRAM/NOR 读、HCA 归约、BFA 符号/位移/累加|
|整向量输出提交|公共 NeuroSim DFF 和已实例化控制路径|一次，既有 16×23 bit 输出寄存|唯一 MAC→公共数字消费边界，等待合适边沿后执行一公共拍|
|普通 SRAM 完整写|有来源的原生完整周期|128 个 16 B 事务，128 个写驱动，一个更新域|每事务 reference 5 ns；含命令/地址/数据捕获、译码、BL/WL 驱动、翻转及恢复|
|写端口接纳及矩阵可计算边界|公共调度|每事务接纳和末次写后可计算端点|只有实际边沿等待；完整周期已含的 capture/setup 不另加一拍|

完整 MAC 不由上游 DCIM 分支 256×256 阵列替代，不添加独立读、符号或累加阶段。普通写不再叠加写驱动、数据捕获或两拍任务握手。`SubArray.writeLatency` 的缺失状态由公共驱动保留；本例完整更新时间来自 128 个有来源的完整写周期与实际端口调度。

## 原生时钟与公共时钟

64 个 MAC 周期在一次整向量接纳后由原生本地控制连续执行，内部轮次不跨回 `lv_core`。这是原始资料所述 64 clock/VMM 和八个位轮次保持静态权重连接的直接调度：已经存入 1024 bit 的整向量足以供应全部输入位，不需要中间握手、权重锁存或新缓存。`inputs.json` 的 E01/E02 与 `cycle_semantics.compute_slot` 是来源。原生周期是物理持续时间，不约束公共数字时钟；只有最终输出才由公共数字消费者接收。

写入与 MAC 输入不同：没有全矩阵 shadow，下一组 128 bit 数据由既有外部口逐事务提供。采用明确工程接口条件：该口只在 `lv_core` 合格边沿接纳下一事务，一次完整原生写成功、恢复后才能接纳后续事务。适配器以 `boundary` 表示边沿接纳，`margin_ns=0` 表示命令/数据 setup 和完整周期恢复已由原生完整写预算包含；它不表示零时间存储或免费额外握手。无额外寄存和写重叠。

末次完整写之后，同样在下一合格公共边沿宣告矩阵可计算。接纳已有完整同步 memory cycle 所含的命令/数据，不能再收一拍 DFF 费。对 reference 的 5 ns 本地写/5 ns 公共周期，各完成时间本来落在合格边沿，新增等待为零。若只把原生写改为 7 ns 而公共周期仍为 5 ns，事务物理延迟是 7 ns，端口串行服务间隔是 10 ns，完整矩阵时间是 1280 ns；streaming 不变。该结果来自真实消费者边界而非把整个公共时钟放慢。

公共输出提交一拍内含其真实路径的 clock-to-Q、逻辑和目的 setup，由公共后端做路径约束，不在每个原生 MAC 后另加 setup 边界。适配器提供的是本地原生服务预算与调度；公共 DFF 的周期计数本身不被称为路径闭合证据。

## 名义算术检查

确定性检查使用零输入、全 −128×−128、−128×127 和混合符号模式。先把权重写成八个二进制位并按二补码重构，再按 8 行组×8 输入位、每轮 16 项×16 输出进行归约；输入最高位系数为 −128。每轮中间值及最终输出均检查 signed 23 bit 容器，结果逐项与整数 VMM 比较。

全 −128×−128 的和为 2,097,152，因此 signed 22 bit 的正端不足，23 bit 容器有必要。此次名义验证不宣称仿真了 D6CIM 晶体管级 HCA/BFA；其时序仍是保留的完整原生周期。

## 参考配置的预期分解与解释

公共完整路径满足 5 ns 目标时，事件式为 `Δ_S = T_D + 64 T_C + T_D = 330 ns`，`T_R = 128 T_M = 640 ns`。两式仅为阶段计数解释；运行值由公共调度器累积事件，不导入旧总延迟。逻辑 streaming payload 为 128 B，完整 resident payload 为 2048 B，分别得 ρ=0.3878788 GB/s、τ=3.2 GB/s、RI*=0.1212121、U*=1.9393939。

结果接近或等于原估算来自完整 MAC/写预算保留、相同完整边界拍数，以及本次已执行公共路径能够达到 5 ns。不能据此宣称 22 nm 对原生 D6CIM 28 nm 宏提供了速度提升。本例容量和输出数也不同于另两个 pilot；相同公共政策不意味着等面积或等成本。

证据入口：兄弟 NVM `analysis/02_sram_dcim/data/inputs.json` 的 E01–E05、E07、E09–E10、`cycle_semantics` 和 `dcim_overrides`；该目录原计算器的完整 MAC 覆盖和完整写替代规则只作为证据，未被运行适配器导入。
