# 05 RRAM：Step 3 适配说明

适配入口为 `rram.build(case, p, backend)`。`case` 保持 Step 2 规范，`p` 从原始输入及 primitive 读取，`backend` 是实际 NeuroSim 调用的返回值；这里不读取旧结果总时间、不调用兄弟目录的计算器。统一驱动负责构建公共后端、执行串行事件、保存完整本地 trace 和导出小型结果。

## 原生组织与两路服务

逻辑 `K=128, N=64`，`B_S=128 Byte`，`B_R=8192 Byte`。八个位平面各保留完整 `64×128` WH-2T1R 宏，每宏四个 `64×32` 子阵列共享 TBL；四个 32 项输入组由 CIMSEL 分时。正常 CIM 与独立 memory BL/SL 写验通路分别建模。

每次 streaming：输入捕获一拍；`8 input bits × 4 row groups × 4 groups of 16 outputs = 128` 个顺序批次；输出提交一拍。每批包含 5 ns 输入选通、5 ns 原生电流建立/漏电补偿、128 个并行公共 SAR 的一次转换，以及 16 条数字通道的两拍重构。输入与权重最高位系数均为 `-128`。

128 个 10-bit SAR 的既有结果状态保持至两拍重构结束。第一拍不假定树结果寄存器；第二拍仍可由原 SAR 码重新完成带符号八平面归约、输入位移及原输出容器的累加。既有输出寄存器共 `64×23=1472 bit`，当前活动组为 `16×23=368 bit`。后一批转换直到累加完成后才开始；没有额外模拟保持、码缓存或重叠流水。

实际 SAR 时间、带负载的数字归约/累加路径、寄存器与控制门路径由公共后端提供。物理服务持续时间不约束公共时钟；公共调度器仅在下一实际数字消费者开始工作时对齐。SAR 宏延迟模型并未给出 WH-2T1R 电流到码的校准或实物误差保证，5 ns 原生前端预算也不是新电路仿真。

## Resident 的有限完成协议

全矩阵保持同一写 rail，只建立一次、退出一次，各 1 µs。512 个顺序 16 Byte 事务覆盖 `64 outputs × 4 subarrays × 2 halves`。每个事务在一个输出 WL、一个 32 项子阵列中，每个位平面的两个组各选择 8 个列，共 `8 planes × 2 groups × 8 lanes = 128` 个物理写目标。枚举检查确认 8192 个逻辑权重各覆盖一次。

局部事务先用两拍完成输入编码数据/地址接收及控制，之后保留两次 RESET 和一次 masked SET。每次尝试的真实顺序为：

1. 一拍地址、极性与 pulse/mask 控制。
2. 100 ns 局部偏置建立、1 µs 原生脉冲、100 ns 局部退偏恢复。
3. 5 ns memory 选通、独立 5 ns memory 前端建立、20 ns 窗口判决/锁存。
4. 一拍 done/mask、组内 all-done 归约和控制状态更新。

原 v3 helper 的恢复项是加法汇总末项；原输入 `service_modes` 明确要求先退偏再读验。本适配按这一物理顺序执行，单次恢复仍只计一次。20 ns 窗口预算已在 Step 2 冻结为独立输入，不随正常 CIM SAR 位数或转换时间变化；窗口比较器与 latch 在该原生服务内，不再重复计入 ADC 或数字比较器。

RESET 首次成功 lane 可屏蔽下一次脉冲，每次仍重新感测全部 lane；SET 仅对目标 1 且未完成的 lane 发脉冲。每批即使全部目标为 0，也保留 SET 时隙。最后一次 SET 后的窗口读取就是本批终验，同时检查目标 1 的 `8–12 kΩ` 双门限和目标 0 的 `≥70 kΩ`，因此不能仅以 SET 活动 lane 的成功作为事务成功。原来源没有额外整矩阵终扫，本实现不凭空增加终扫。

每 lane 两个比较器按目标选择参考：目标 1 使用 LRS 的 8/12 kΩ 两端，目标 0 使用 HRS 的 70 kΩ 门限且另一路结果不参与。参考选择包含在原生窗口预算，不暗增第三个比较器或将资源变为 384 个。

串行控制器只在本批终验成功后推进事务地址，以 sticky fail 阻止发布，不需要 512 bit 的历史 done 数组。Step 3 显式实例化 32 bit 控制状态：9 bit 事务地址、2 bit retry、2 bit phase、ready/fail 和其余控制位；另外保留原先 128 bit 编码 staging、128 bit mask/done。32 bit 是实现控制接口的小型工程条件，不是新增数据缓存。公共后端检查窗口输出、mask、128 路归约到控制状态的完整路径。

所有事务成功、rail 退出后，已有 ready 接口在首次满足 setup 的时钟边沿发布。`matrix_publish` 是显式 boundary 事件，计入 setup 与边沿等待，不另加完整一拍。它落实 v3 的全矩阵成功发布条件，也避免把物理 rail 退出误当作免费数字握手。

只在全部活动 cell 于声明次数内达窗时计算成功 payload。两次 RESET 后仍失败、SET 低于 8 kΩ、SET 高于 12 kΩ，以及未编程 HRS 被扰动低于 70 kΩ，都会失败且不发布。1 µs 波形来自跨 stack 一手来源；2/1 是已有有限完成工程情景，二者均不表示 WH-2T1R 同栈实测可达性、良率或统计典型值。V1.4 缺失的 aggregate `writeLatency` 继续为 `null`，完整混合 `T_R` 则由这些有来源的原生阶段与实际控制调度相加。

## 时间解释与验证边界

原 v3 对照由原输入独立回放得到：`delta_S = 5130 ns`，局部事务 `3730 ns`，完整 `T_R = 512×3730+2000 = 1911760 ns`。新结果必须读取统一入口实际产生的结果；正常路径变化应分解为公共 SAR 转换、真实数字周期及消费者对齐，写侧变化应分解为独立 control/verify 边界与发布。保留脉冲、局部切换和 rail 服务不因采用 22 nm 外围而改变。

适配返回 `local_transaction` 和 `isolated_transaction` 两份事件：前者无 rail 起退，代表已经建立 rail 的局部事务；后者包含一次 rail 起退与 ready 发布。两者都必须实际调度得到时间，不能将完整矩阵时间除以 512 冒称孤立 16 Byte 请求时延。全矩阵 T_R 仅含一次 rail 生命周期。

数值诊断使用三个完整逻辑尺寸的确定性向量/矩阵：两者均为 -128、-128 乘 127、混合符号模式。先产生理想校准的 0–32 部分和，再选择诊断编码 `q=16s`，用 `q>>4` 解码并执行八平面和输入位的带符号重构；结果逐个输出对照直接 INT8 点积，并检查每次累加均在 INT23 范围。`q=16s` 是可解释的理想诊断编码，不是补造实物电流到 SAR 码的传递函数。10-bit 名义容器与原 ENOB=8 的量级条件分别记录；未证明器件精度或量化偏差。

另外用给定阻值的确定性控制 fixture 检查成功、RESET 超时、LRS 上下界越界、masked HRS 扰动和全零 SET 保留时隙；这些测试验证协议逻辑，不预测写成功概率。实际模块调用、完整负载路径及跨案例敏感性由公共入口和独立复跑负责。
