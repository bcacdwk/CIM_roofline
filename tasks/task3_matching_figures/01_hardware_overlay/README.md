# 候选 A：硬件能力与完整装载复用

**回答的问题：** 在原生完整 resident 装载后，需要怎样的复用次数，才能使两路服务达到平衡？保留十类硬件的绝对能力位置，同时叠加少量已有 workload 状态。

图为跨双栏 **7.16×4.35 in**，正文和标签约 8–10 pt；`figure.png` 供预览，`figure.pdf`/`figure.svg` 为矢量版本。从仓库根复现：

```sh
PYTHONDONTWRITEBYTECODE=1 /opt/anaconda3/bin/python tasks/task3_matching_figures/01_hardware_overlay/build.py
```

输入为只读 `../shared/data.json`。`plotted_data.json` 保存 30 个点的精确坐标、原生来源指针、圆参数和需求 U；`validation.json` 核对点数、圆完整入框、等对数比例与物理尺寸。未调用任何会改写 Task I 的生成器。

横轴是原始 resident 更新能力 τ，纵轴显式改为 σ=Nρ，即将输入率按各自原生输出维 N 换算成完整矩阵等效的 streaming 能力。纵轴不是原始 ρ。平衡线 σ=Uτ；线以上为 resident-bound，线以下为 streaming-bound。深色 U=128 线配合左上方说明，其余三条线独立使用相同判定，不设一层固定分区底色。

U=1、128、1K、128K 来自已验收 Table II(a) 的 GEMM W[128,128]，覆盖首次使用、若干中间阈值附近、中高复用和 NOR 长情景跨界。对所有十类图点，这四个 U 只是**原生完整装载的复用要求参照**；只有原生 K=N=128 的子集直接对应 W[128,128] 字节边界。图不声称该单一算子已经部署到其余不同形状的硬件；具体 QKV 映射由候选 B 单独建立。

可以支持的观察：

1. 相同 U=128 下，典型 SRAM、Gain-cell、PCM、FeRAM 和 FeFET 位于 streaming 一侧；MRAM 典型 U*=132.74 则略在 resident 一侧，不能因视觉贴线就判为精确平衡。
2. RRAM、NAND、NOR 需要依次更高的原生完整装载复用；这反映摊销要求，不构成综合性能排名。
3. NOR 的 U=128K 参照跨过典型与短情景，却仍未跨过长情景（U*=253826）。判定来自真实点，不能从圆内部推断额外可实现状态。

圆在 log₁₀(τ), log₁₀(σ) 平面按 Task I 原规则构造。对每种介质，ρ→Nρ 是 log 空间的固定纵移；三点成对关系保持。圆仅是有限情景摘要，不是概率、置信区间或能力包络。完整服务定义、上界限制和统一单位见[共同说明](../shared/README.zh.md)。
